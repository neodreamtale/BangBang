# 开发环境配置指南

## 问题说明

在 Windows 环境下使用 Dev Container 时，文件系统监听可能会遇到问题，导致热更新失效。这是由于：

1. **文件系统事件传递链路复杂**：Windows → WSL2 → Docker → Container
2. **inotify 事件丢失**：在多层虚拟化环境中，文件变化事件可能无法正确传递
3. **文件系统差异**：NTFS → ext4 → overlayfs 的转换过程中可能丢失监听能力

## 解决方案

### 方案1：直接挂载 + VSCode（推荐，您当前使用的方案）

**优势：**
- 文件监听更可靠
- 开发体验更流畅
- 减少中间层

**使用方法：**
```bash
# 启动开发环境
npm run docker:dev

# 查看日志
npm run docker:dev:logs
```

### 方案2：强制 Polling 模式

如果需要在容器内开发，可以使用 polling 模式：

```bash
# 使用强制 polling 模式
npm run dev:watch
```

## 配置优化

### 1. Next.js 配置优化

已在 `next.config.ts` 中添加：
- 动态轮询频率调整
- 禁用文件系统缓存
- 特殊的挂载文件系统配置

### 2. 环境变量

开发环境可设置：
```bash
WATCHPACK_POLLING=true      # 启用 webpack 轮询
CHOKIDAR_USEPOLLING=true   # 启用 chokidar 轮询
```

### 3. Docker 配置

- 使用匿名卷提高 node_modules 性能
- 正确挂载源码目录
- 设置必要的环境变量

## 性能优化建议

1. **轮询频率调整**：
   - 开发环境：1000ms（快速响应）
   - 资源受限：5000ms（节省资源）

2. **排除不必要的目录**：
   - node_modules
   - .next
   - .git

3. **使用 .dockerignore**：
   - 减少构建上下文大小
   - 避免监听不必要的文件

## 故障排除

### 热更新仍然不工作？

1. **检查端口映射**：确保 3001 端口正确映射
2. **检查文件权限**：确保容器内有读写权限
3. **检查网络连接**：确保浏览器能正确连接到开发服务器
4. **检查环境变量**：确保 polling 相关变量已设置

### 性能问题？

1. **降低轮询频率**：将 1000ms 改为 3000ms 或 5000ms
2. **使用更具体的 ignored 规则**
3. **考虑使用 SSD 存储**

## 最佳实践

1. **开发时使用方案1**（直接挂载）
2. **CI/CD 时使用标准 Docker 构建**
3. **定期清理 Docker 缓存和卷**
4. **监控资源使用情况**
